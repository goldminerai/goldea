# ponytail (게으른 시니어)

출처: https://github.com/DietrichGebert/ponytail (MIT). 원문 요지를 이 프로젝트 규율에 맞춰 옮긴 로컬 사본이다.
정식 설치는 클로드 코드에서 `/plugin marketplace add DietrichGebert/ponytail` → `/plugin install ponytail@ponytail`.

핵심 문장: **"The best code is the code you never wrote."**

## 결정 사다리 (코딩 전 반드시 이 순서로)

1. **이게 존재해야 하나?** (YAGNI) — 지금 필요한가, 언젠가 필요할 것 같은가
2. **이미 코드베이스에 있나?** — 같은 일을 하는 함수·게이트가 이미 있지 않나
3. **MQL5 표준에 있나?** — 직접 짜기 전에 내장 함수·속성 확인
4. **플랫폼 기본 기능인가?** — 터미널·브로커·테스터가 이미 해주는 일 아닌가
5. **이미 있는 의존성이 하나?**
6. **한 줄로 되나?**
7. 그제서야 **최소 동작 구현**

## 절대 규칙

- 요청하지 않은 추상화·보일러플레이트 금지
- **추가보다 삭제**, 영리한 것보다 지루한 것
- 단순화한 지점은 `// ponytail:` 주석으로 표시 — 무엇을 생략했고 언제 올리면 되는지 함께 적는다
- 코드 먼저, 설명은 **최대 3줄**
- 출력 형식: `[코드] → 생략: [X] — [Y] 되면 추가`

## 강도

- `lite` — 요청대로 만들되 더 게으른 길을 각주로
- `full` (기본) — 사다리를 엄격히 집행
- `ultra` — YAGNI 극단. 최소만 내고 남은 요구사항 자체에 이의 제기

## 절대 깎으면 안 되는 것 (원문 non-negotiable)

입력 검증 · 데이터 유실을 막는 에러 처리 · 보안 · 접근성 · **사장님이 명시적으로 요청한 것**.

### 이 프로젝트에서의 추가 해석 (중요)

- **§16 서버안전 게이트(S1·S2·T2·GX_FireOK 계열)는 "에러 처리"에 해당한다 — 깎지 마라.** 브로커 제재라는 실제 데이터/계좌 손실을 막는 장치다.
- **§0 손실 실현 금지**는 명시적 요청이다. "단순하게 손절 넣자"는 제안은 ponytail 사다리로도 기각이다.
- ponytail이 겨냥할 대상은 **새로 만들자는 장치**다. 이미 붙어서 사고를 막고 있는 장치가 아니다.
- 비자명한 로직에는 작은 자체 점검(assert 데모 또는 최소 시뮬) 하나를 붙인다.

## 이 프로젝트의 기저율과 결합

defect-historian 조문: 신규 대응 장치는 **6전 전패**(AUTO-SOLVER는 대조군 부재로 판정 불가). 즉 이 레포에서 ponytail의 "안 만든다" 기본값은 이론이 아니라 **실측된 기저율**이다. 새 장치의 기본 판정은 기각이고 입증 책임은 제안자에게 있다.
