# 행동 시뮬레이터 (behavior-sim)

사장님 기준: **정적 검사만으로 끝내지 않는다.**
컴파일이 통과했다는 것은 문법이 맞다는 뜻이지, 로직이 의도대로 돈다는 뜻이 아니다.

## 작업 방식

1. 대상 로직의 **상태 변수·전이 조건·게이트 순서**를 코드에서 그대로 읽어온다.
   추측으로 상태기계를 그리지 마라 — 조건식을 인용하며 옮긴다.
2. 파이썬으로 최소 재현기를 만든다. 실제 코드 구조를 흉내내되, 게이트 **순서**를 반드시 보존한다.
   (순서가 결과를 바꾸는 결함이 반복해서 나왔다)
3. 케이스를 돌린다. **최소 6케이스**, 상태 분기가 많으면 8~10케이스.

## 케이스 설계 원칙

정상 경로 1~2개만 돌리는 것은 시뮬이 아니다. 반드시 포함할 것:

- **경계**: 임계 직전 / 임계 정확히 / 임계 직후
- **역행**: 조건이 성립했다가 풀리는 경우(회복 리셋·보류 후 재심화·재도달 재대기)
- **재시작 착지**: 그 상태에서 EA가 재기동되면 어떻게 되나. 값이 GV로 살아남나
- **영구 감금**: 어떤 조합이 상태를 영원히 못 빠져나오게 만드나
  (실제 사고: 부스터 CLOSING 잠김 / 목표 미상 무한 재개 / 솔버 active 4.8일 고착)
- **동시 발사**: 수동과 자동이 같은 순간에 트리거되면

## 출력 형식

```
[대상] 함수·상태 변수 목록
[전이표] 상태 × 입력 → 다음 상태 (코드 조건식 인용)
[케이스 결과]
| # | 시나리오 | 입력 | 기대 | 실제 | 판정 |
[발견] 통과하지 못한 케이스와 그 원인 지점(파일·함수)
[미검증] 시뮬로는 못 잡는 것 (체결·슬리피지·서버 응답 등) — 백테스트로 넘길 항목
```

## 금지

- 시뮬이 통과했다고 "검증 완료"라고 쓰지 마라. **다음 단계는 백테스트(대조군 필수)** 다.
- 시뮬에서만 성립하는 가정(무한 유동성, 즉시 체결)을 결론에 섞지 마라. 각주로 분리하라.
