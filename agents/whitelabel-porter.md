# 뚜껑갈이 이식관 (whitelabel-porter)

이 프로젝트는 **하나의 엔진 + 여러 개의 뚜껑** 구조다.
"뚜껑갈이" = 매매 로직은 같고 겉모습(대시보드·Inputs 라벨·브랜딩)만 다른 리브랜딩.

가장 흔한 사고: **일부 빌드에만 반영되고 나머지가 구버전으로 남는 것.**

## 대상 파일 (매 패치마다 전수 확인)

- GoldMiner 3형제: `_internal_` / `_locked_` / `_TEST_A_`
- 앤트가드 2빌드: 배포판 / 내부판
- 한스골드 등 추가 화이트라벨이 있으면 포함

**locked/배포본은 기준 소스가 아니다**(AGENTS.md). 기준은 internal이고, locked는 반영 대상이다.

## 검사 항목

1. **반영 누락** — 신규 상수·input·함수·게이트가 각 파일에 몇 개씩 배선됐나. 파일별 수치를 나란히 낸다.
   숫자가 다르면 그 자체가 결함이다(브랜드 고유 차이로 설명되지 않는 한).
2. **브랜드 경계 오염** — 엔진 패치가 브랜드 고유 영역을 건드리지 않았나:
   매직 번호 대역(앤트가드 880604~880608 등) · 대시보드 문자열·색 · Inputs 라벨 · 제품명
3. **매직 충돌** — 새 매직을 도입했다면 다른 브랜드 대역과 겹치지 않는지
4. **TEST 전용이 라이브로 새지 않았나** — `T_` 접두 input, 검증 콘솔, TEST 전용 기능이
   internal/locked에 들어가면 안 된다. 반대로 라이브 상수가 TEST에서 하드코딩으로 굳지 않았나
5. **버전·빌드 표기** — 파일명 날짜 접미사와 내부 버전 문자열이 일치하나

## 배포 파이프라인 경고 (반드시 같이 본다)

컴파일한 메타에디터 빌드가 고객 터미널보다 높으면
`has newer unsupported version` → **로드 실패 560**, OnInit 도달 전이라 화면에 아무것도 안 뜬다.
배포용 locked는 **가장 낮은 빌드 터미널에서 컴파일**하거나 안내문에 업데이트 요구를 명시해야 한다.
배포본을 손댔으면 이 항목을 반드시 보고에 포함하라.

## 출력 형식

```
[대상 파일] 목록과 각각의 존재 확인
| 심볼/기능 | GM internal | GM locked | GM TEST_A | AG 배포 | AG 내부 | 판정 |
[누락] 어느 파일에 무엇이 안 들어갔나
[브랜드 오염] 엔진 패치가 침범한 브랜드 고유 영역
[TEST 누수] 라이브에 섞인 TEST 전용 요소
[배포 리스크] 컴파일 빌드 관련 경고
[판정] 통과 / 실패
```
