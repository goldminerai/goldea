# 골드 업글 — 전략 분석 트랙

> 기존 엔진 유지보수 라인과 **분리된 별도 트랙**입니다.
> 여기서는 파라미터·구조를 분석하고 후보를 검증합니다. 엔진 코드를 직접 고치지 않습니다.

개설 2026-07-31 · 정본 기준 `GoldMiner_v5_5_4_internal_20260730.mq5` (984,082 B)

---

## 이 트랙이 뭔가

기존 라인은 **"고장 난 걸 고친다"** 였습니다 — 결함 발견 → 변경표 → 패치 → F7 → 백테스트.

이 트랙은 **"더 나은 설정을 찾는다"** 입니다 — 조합 생성 → 산술 스크리닝 → 워크포워드 → 몬테카를로 → 평탄대 확인 → 채택 제안.

**성격이 다르므로 규율도 다릅니다.** 결함 수리는 "안 고치면 사고"지만, 파라미터 탐색은 **"잘못 고르면 과최적화"** 입니다. 방어 장치가 반대 방향으로 필요합니다.

---

## 경계 — 이 트랙에서 하지 않는 것

- **엔진 코드를 직접 고치지 않습니다.** 채택 제안까지가 여기 일이고, 실제 패치는 기존 라인의 변경표 절차를 탑니다
- **결함 수리를 여기서 하지 않습니다.** R3·3상태 버튼 같은 건 기존 라인 소관입니다
- **§0 손실 실현 금지, §16 서버안전은 탐색 대상이 아닙니다.** 헌법과 안전장치는 파라미터가 아닙니다

## 규율 — 이 트랙 고유

1. **단독 런은 판정이 아니라 관찰입니다.** 대조군 A/B 필수 (기존 조문 승계)
2. **최고 성적 1개를 고르지 마십시오.** 이웃 파라미터에서도 성적이 유지되는 **평탄대**에 있는 후보만 채택합니다
   → 근거: [MQL5 art.22578](https://www.mql5.com/en/articles/22578) — *"예쁜 숫자를 robust함과 혼동하지 마라"*
3. **워크포워드 통과 필수.** 인샘플 최적화 → 아웃샘플 검증, **수익 난 forward 구간 비율 > 50%**
4. **몬테카를로 통과 필수.** 트레이드 순서 부트스트랩 → **평균 ÷ 산포**로 판정
5. **같은 체급끼리만 비교합니다.** 합랏이 작아서 부동손실이 준 건 개선이 아니라 덜 거래한 것
6. **PF가 지나치게 높으면 의심하십시오.** 최적화에서 PF 8을 넘는 설정은 forward에서 무너집니다
7. **기저율을 기억하십시오.** 이 레포에서 신규 대응 장치는 6전 전패입니다. 조합이 수백 개면 우연히 좋아 보이는 게 반드시 나옵니다
