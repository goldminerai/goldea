## 이게 뜻하는 것

### 1. arm 괴리 규명이 여기서는 불가능하다

계획했던 "라이브 저널에서 `[LHEDGE] ARM` 시점의 실제 부동손실 추출"을 이 PC에서 할 수 없습니다.

**필요한 것**: 오르비스 라이브가 도는 VPS(또는 다른 PC)의
```
<터미널 데이터폴더>\MQL5\Logs\2026xxxx.log     ← EA 로그 (Experts 탭)
<터미널 데이터폴더>\logs\2026xxxx.log          ← 터미널 저널
```
`[MOMANTIC][LHEDGE]` 로 필터하면 ARM/DEPLOY/FIRE 전 이력이 나옵니다.

### 2. 빌드–계좌 대응은 여전히 추정 단계다

`locked` 빌드는 `const SRV_GMT_SUMMER = 3 / WINTER = 2` 오르비스 소성이므로 **오르비스 전용**이고,
`internal`은 `input`이라 브로커 무관입니다. 여기서 **오르비스 라이브 = locked** 라는 추정이 나오지만,
**실제로 무엇이 붙어 있는지는 이 PC에서 확인할 수 없습니다.**

이게 중요한 이유 — 만약 오르비스가 `locked`로 돌고 있다면:
- `locked`에는 **7/31 축(ARM_USD + L11 5.3)이 없습니다**
- 즉 오르비스는 **구 랏 기준(1.73랏) arm**으로 돌고 있고, "너무 빨리 발동한다"는 관측은 **당연한 결과**입니다
- 그렇다면 P6(모집단 777 제외)를 재론할 필요가 없고, **전파만 하면 해결**입니다

반대로 오르비스가 이미 달러 축 빌드로 돌고 있는데도 빨리 발동한다면, **모집단 오염이 실재**합니다.

**두 경우의 처방이 정반대이므로, 확인 전에는 어느 쪽으로도 움직이면 안 됩니다.**

### 3. 부수 확인 — 배포 파이프라인 리스크

`BB16F` = XM Global MT5 에서 컴파일하고 있습니다. 앞서 확인된 `has newer unsupported version` / 로드 실패 560 문제와 직결됩니다 —
**컴파일 터미널의 빌드가 고객·운용 터미널보다 높으면 `.ex5`가 로드되지 않습니다.**
Vantage 터미널은 build 6074인데(7/31 저널), XM 터미널 빌드는 별도 확인이 필요합니다.
