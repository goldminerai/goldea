00 — Overview

엔진을 한 장으로

이 EA는 방향을 예측하지 않습니다. 방향 판정 함수가 코드에 존재하지 않습니다. BUY와 SELL 사이클이 서로를 참조하지 않고 독립적으로 돌며, 가격이 오면 층을 쌓고 비용을 넘긴 순간 묶어서 나갑니다. 이기는 방법은 예측이 아니라 손실을 실현하지 않고 버티는 구조입니다.

§0 — 손실 실현 금지 (헌법)

"손절 없이 약수익 회복"이 이 EA의 본질입니다. 청산 주체 6개 전부가 발사 전에 묶음 손익 − 비용 ≥ 0을 확인하며, 손실 다리를 단독으로 닫는 경로는 코드 어디에도 없습니다. 마스터 손절 UseCrushGuard는 기본 false입니다.

01 — Glossary

약어 사전

이 문서와 코드에 나오는 약어를 먼저 정리합니다. 코드에 실물이 없는 문서 전용 용어는 따로 표시했습니다.

기계 이름

통문
그룹 TP. 한 사이드 전체를 하나의 목표가에 묶어 통째로 나가는 출구. 서버 지정가로 상주하므로 EA가 죽어도 브로커가 체결합니다.
셀프 그라인딩
같은 사이드 안에서 수익 다리(연료)와 손실 다리(대상)를 묶어 동시 청산. 레이어 통째 단위, 부분청산 없음.Grind_Try
XGrind (교차)
물린 사이드에 자기 연료가 없을 때, 반대편 수익을 연료로 끌어와 구조. 연료측에 확장TP를 걸어 먼저 못 빠져나가게 잠급니다.
OVERCAP-D
L13+ 리필 다리 전용 별도 차선. 유일하게 부분청산(0.05랏 청크)을 씁니다.
LHEDGE / 방패
레이어헷징. 물린측 손실이 임계에 닿으면 반대 방향으로 사다리 방패를 전개.매직 111
WKL / WLU
주말락. 금요 마감 전 순노출의 절반을 헷지로 덮고 섬으로 격리해 갭을 무력화.매직 999 · WKL=상수 접두, WLU=함수 접두
PM / 러쉬 / 부스터
프로핏메이커. 시장 가드를 전부 무시하고 도는 독립 채굴 엔진. 수동 버튼 발동.매직 555
SOLVER / 해결사
수동 버튼으로 최악 손실 다리 1개를 신규 진입과 묶어 합산 평단에서 동반청산.매직 777
돌려깎기 / EXITPLAN

02 — Lifecycle

생애주기 5구간

코드에 IDLE/BUILDING/… 같은 enum은 없습니다. CycleState 구조체의 필드 조합으로 암묵 표현됩니다. 아래 구간 이름은 설명용 라벨이고, 전이 조건은 전부 실제 조건식입니다.

핵심 설계 — 소각하면 증차가 되살아난다

구간 4에서 구간 2로 돌아가는 금색 점선이 이 엔진의 심장입니다. 캡 판정 기준이 층번호 래치가 아니라 랏 예산이기 때문에, 그라인딩으로 비운 만큼은 곧바로 재진입이 허용됩니다.

층번호도 복원됩니다 — newL = FindMaxLiveLayer() + 1. L10 연료를 태웠으면 살아있는 최대가 L9가 되고, 다음 증차는 다시 L10으로 원래 랏·원래 간격으로 들어갑니다.

구 방식(층번호 래치)은 소각 후 재진입을 영구 차단해서 연료가 재생되지 않았고, 결국 그라인딩이 고사했습니다(5월 실증). 그래서 바뀐 겁니다.

04 — Entry

진입 — 3중 게이트

최초 진입(L1)은 사다리를 타지 않는다

L1 랏은 GetLotForLayer(1, …)이 아니라 GetActiveLot()을 직접 씁니다. 결과값은 같지만 경로가 분리되어 있어 개조할 때 함정입니다.

double GetActiveLot()
{
   if(!UseAutoLot) return BaseLot;
   double bal = AccountInfoDouble(ACCOUNT_BALANCE);
   double lot = MathFloor(bal / GetLotUnit()) * BaseLot;   // 공격 3.5만 / 일반 5만 / 안전 7만 / 방어 10만
   return NormalizeLot(MathMax(lot, BaseLot));
}
→ 체결 후 state.baseLotForCycle 에 고정. 이 사이클의 사다리 base 가 됩니다.
방향은 어떻게 정하나 — 정하지 않습니다

BUY/SELL 사이클은 서로를 참조하지 않는 독립 상태기계입니다. 같은 틱에 두 방향 모두 posCount==0 && canOpenNew면 양쪽이 동시에 L1을 엽니다. 추세·지표로 방향을 고르는 함수는 코드에 없습니다.

유일한 편측 강제는 드리프트 원웨이 — 추세 가드 발동 중에는 추세 역방향 신규만 거부합니다 (진행 중 사이클의 증차는 무관).

FLUSH 관문 — 반대편 만재 방지 장치

FLUSH 국면에서 태어난 사이클에는 표식이 찍히고, 그 표식이 L5에서 전개를 세웁니다.

// 표식 각인 — 신규 진입 직전
state.bornInFlush   = (g_dm_state == DM_FLUSH);
state.flushLockBase = SumOpenLotsBySide(반대방향);   // 스냅샷

// 관문 — L5 초과 시도할 때
if(bornInFlush && !flushGatePassed && gateNextL > 5)
{
   fgTimeOK = (경과 ≥ 4시간);
   fgCutOK  = (반대편 락 ≤ 스냅샷 × 0.80);      // 20% 감소
   if(fgTimeOK || fgCutOK) flushGatePassed = true;  // 사이클당 1회 래치
   else return false;                              // 보류(차단 아님)
}

해제 경로는 둘 — 4시간 텀 또는 반대편 락 20% 감소. FLUSH 자체가 끝나면(포지션 0) 표식이 즉시 소멸합니다. 또한 bornInFlush 사이클은 전 구간 시간 게이트가 ×2가 됩니다.

현재 꺼져 있는 게이트

USE_NIGHT_LOCK = false (8시락) · USE_DD_GUARD = false (DD 가드) · UseDdmDistance = false (DDM 거리 확대 — v5.5.0에서 철회) · LHEDGE_ARM_LOTS = 1.73 (달러 모드라 실행되지 않음). 코드는 살아 있으니 켤 때 영향 범위를 먼저 확인하십시오.

09 — Scenarios

상황별 분기 — 이럴 땐 어떻게 되나

가격이 다음 층에 닿았는데 시간이 안 찼다

대기합니다. 매 틱 재평가되어 시간이 차는 순간 그 시점 가격으로 들어갑니다. 그 사이 가격이 더 갔으면 더 좋은 자리, 되돌아왔으면 거리 미달로 다시 대기입니다. 설계 의도가 코드 주석에 명시되어 있습니다 — "대기 중 가격이 되돌아오면 그룹 TP로 자연 청산 / 더 역행하면 시간 만료 후 진입 강행".

캡에 걸렸는데 가격이 계속 간다

1단계 여유가 최소랏 이상 남았으면 랏만 축소해 정확히 캡에 착지합니다. 이 다리는 들어갑니다.
2단계 그 후로는 매 틱 조용히 스킵 — 가격이 아무리 가도 다리는 안 늘어납니다.
3단계 동시에 고정구역(노출 ≥ 2.28)에 진입해 다음 다리는 0.22 고정 + 2시간 쿨다운이 됩니다.
4단계 room을 만드는 건 청산 계통입니다. 소각으로 열리면 원래 층 번호로 재진입합니다.

반대 방향이 이미 물려 있는데 신규 진입 요청

기본은 허용입니다. 캡이 방향별로 독립이라 반대편 물림은 이쪽 여유에 영향이 없습니다.

제어는 세 가지로 들어갑니다 — 드리프트 원웨이(추세 역방향 신규만 차단) · FLUSH 관문(신규는 열리되 L5에서 정지) · 레이어헷징 각인(물린측 노출이 선을 넘으면 방패 발동 기산).

"반대편이 물렸으니 이쪽을 막는다"는 전면 게이트는 v5.5.0에서 삭제됐습니다. 라이브 7/14에 교착이 났기 때문입니다 — BUY가 물리자 SELL 신규가 18시간 40분간 0건이 되어 XGrind 연료가 고갈됐습니다.

폐장 직전 / 프리틱

진입 거래시간 밖이면 canTrade=false로 신규·증차 정지, 수익 포지션만 정리합니다. 마감 120분(드리프트 중이면 180분) 전부터는 마감창 플래그가 켜집니다.

청산 세션 게이트가 EA 주도 청산을 전부 막습니다. 단 통문은 서버 지정가로 상주하므로 브로커가 체결합니다.

주말 갭 2시간 이상 무틱이면 SafeResume이 재발동해 15초 + 5항목 검사를 통과해야 재개합니다. 주말락 재진입 시에는 금요일에 세운 계획을 전부 파기합니다 — 낡은 계획이 월요일 첫 프리틱에 발사되어 59초간 594회 재시도 폭풍이 났던 사고 대응입니다.

재시작 직후 (기존 포지션 있음)

본대는 포지션 스캔으로 층수·기준가·직전 체결시각까지 복원합니다(시간게이트 무풍 봉합). base는 복리 주입을 막기 위해 GetActiveLot()이 아니라 테이블 역산으로 구합니다.

주의 bornInFlush 표식은 복원되지 않습니다 — 재시작하면 FLUSH 관문이 풀립니다. XGrind 무장과 그라인딩 상태도 리셋됩니다.

MT5 업데이트 후 재시작 / 타임프레임 변경

알고트레이딩 OFF → ServerReady() 실패 → 화면 ALGO OFF 빨강, 로그 ALGOOFF. 터미널에서 버튼을 켜면 다음 틱에 자동 재개됩니다(별도 리셋 불요).

타임프레임 변경 = OnInit 재실행 → GV 복원 + 포지션 스캔으로 상태는 보존되지만 SafeResume 15초 홀드가 걸립니다. 화면에 RESUME -15s 앰버로 표시됩니다.

폐장 중 재시작이면 틱이 없어 1초 타이머로 부팅하고, 재개 검사는 stale에 걸려 15초가 지나도 안 풀립니다. 이건 정상 동작입니다.

강제청산(CLOSE ALL)을 눌렀다

1차 클릭은 무장(4초), 4초 내 2차 클릭에서 전량 청산 + 정지 래치가 걸립니다. 청산만 하면 다음 틱에 마틴이 새 사이클을 열어 청산이 무의미해지기 때문입니다.

래치 중에는 OnTick 최상단에서 전 로직이 차단되고 2초 주기 잔여 재청산만 돕니다. PM은 GV까지 삭제되어 재적용해도 부활하지 않습니다. 해제는 EA 재적용뿐입니다 — 해제 코드가 파일에 존재하지 않습니다.

라이선스가 운용 중 만료됐다

5초 주기 타이머가 재시작 없이 즉시 잡아 신규·증차를 동결합니다. 기존 포지션의 청산·TP 관리는 계속됩니다. 화면은 전 버튼을 숨기고 "운영 정지 / 기존 포지션은 정상 관리됩니다" 오버레이를 띄웁니다.

참고 — remotePause는 신규만 차단하고 PM·해결사·증차는 그대로 돕니다. remoteStop·licStopped는 신규 + 증차 + PM까지 동결합니다.
