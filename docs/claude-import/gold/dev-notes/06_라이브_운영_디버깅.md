## 라이브 정지 진단 — DM_FLUSH 영구 교착 (7/15, v5.5.0 개편의 발단)
- 발단: "예전 버전이면 바이 추가진입도 하고 셀 대응도 하는데 지금은 둘 다 안 함". 비교 기준 v4.0.3 broadcast(9,200줄). 원칙 "이슈를 이슈로 덮지 말고 근본 오류 먼저".
- 라이브 실측(Eric 500025/500064, base 0.01): BUY 7다리 통문TP 4055.49, 04:46 L10 이후 딜 0 / SELL 신규 21:01 이후 0. 랏 사다리 = 설계÷1.5 = DDM 상시감축(v4.0.3엔 없음).
- **증상① "바이 추가진입 안 함" = 정상**: L11 요구간격 = 300pt×PROG_MULT_L11(8.3)=$24.90, DDM 거리연계 ×√1.5=$30.50. 현 gap $7~10 미달 → L11은 4008.85까지 내려가야 진입. v4.0.3도 동일($24.90) → 구버전이어도 안 들어갔음(사장님 기억 착각). 단 UseDdmDistance가 22% 멀게 한 건 사실.
- **증상② "셀 대응 안 함" = 진짜 결함, DM_FLUSH 영구 교착**: drift 해제 시 openPos>0이면 g_dm_state=DM_FLUSH → canOpenNew가 !=DM_FLUSH 요구 → 신규 사이클 전면 차단. FLUSH 해제 조건은 BUY+SELL==0(전량 청산)뿐 + 자정 리셋도 보류 → BUY가 깊이 물리면 SELL 영구 연좌.
- 핵심 논거: FLUSH 게이트는 의도 기여 0(신규는 posCount==0에서만 열림 → FLUSH 대상 방향은 어차피 차단). 실제 하는 일 = 반대 방향 신규 차단(연좌)뿐. v4.0.3과 바이트 단위 동일 = 원래부터 있던 설계 결함.
- 연쇄 피해: FLUSH로 SELL 영구 소멸 → XGrind 연료원 0 → 1:1 페어(L1+L9)의 진짜 원인 / 레이어헷징 L11 도달 불가 → 방어 무력화. v5.4.1 L1PAIR는 증상 완화, FLUSH가 원인. → v5.5.0 FLUSH 반대편 관문으로 해결.
- DEBUG_LEVEL이 v5.4.0 소성 때 하드코딩 내부화(주석은 "1로 올리면 차단사유 표시"인데 재컴파일 필요).

## 재구동 인식 — MT5 업데이트/재시작 후 "화면 정상·진입/버튼 불능" (7/30)
- 공통 이슈: MT5 버전/서버 업데이트 재시작 후 화면(대시보드)은 정상인데 진입·버튼 동작 안 됨. 타임프레임 변경 시에도 발생 맥락.
- 진범: §16 ServerReady 침묵 차단인데 대시보드 canTradeDash가 ServerReady 미포함 → 화면 MINING 정상 표시. 차단사유 로그도 빈 사유. 버튼: RESCUE/BOOSTER/CLOSE ALL 각각 침묵 실패. 타임프레임 변경=OnInit 재실행→SafeResume 15초 홀드(화면 미표시).
- 부스터 잠김(B1): 버튼 2상태 분기(running→Stop/아니면 Start)인데 softClose 중 running=true 유지 → 재클릭=Stop 무시, Start는 전량청산 후에만 → 감금. 수리 = 3상태 + PM_Resume()(수동마감=같은 판 이어감 / 목표달성 자동마감=새 판). 보완 (가) 목표 미상(blockTarget=0) 상태 새 판 정의 (나) 폐장 부트 GX_SessionOpen 게이트.
- 복원 매트릭스: 202604·555·777·111·999 전부 양호. 신규 X-R1(XGrind 무장 중 재시작 시 xgArmed 리셋인데 서버 확장TP 잔존) → 7/31 재검수로 실효 "최대 3초 앞당김" = 무의미, 제거 권고·삭제.
- 구현(앤트가드 v3.34 + GM v5.5.4 _20260730): R1 대시보드 집행불능 축(NO LINK/ALGO OFF 빨강·RESUME 앰버) / R2 차단사유 로그 세분 / R3 Sweep 실패 로그 / B1 부스터 3상태.
