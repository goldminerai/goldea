## 2. ⚠ VT 3차 제재 리스크 — 실재 확인

locked 는 VT에 쓸 수 없습니다. 락업 소성이 걸려 있기 때문입니다.

```
internal 806:  input int  SRV_GMT_SUMMER = 3;   ▸ 서버 GMT — 여름 (브로커별 필수 확인)
locked   806:  const int  SRV_GMT_SUMMER = 3;   ← 오르비스 GMT 3/2 고정
```

따라서 **"VT 최신판 교체(T3)"의 후보는 internal 뿐인데, 그 internal 에 T1·T2가 없습니다.** 2차 제재의 진범(데드밴드 $0.05 붕괴 + modify retcode 무시)이 그대로 살아 있는 파일을 VT에 올리면 3차 제재는 재발이 아니라 예정된 결과입니다.

→ **결정 필요:** VT에 실제로 무엇을 붙이실 계획인지(GM internal 계열 / 앤트가드 v3.34). 앤트가드 v3.34는 7/30 패키지 탑재가 확인된 빌드라 그 경로면 리스크가 없습니다.

## 4. ✅ 반증되어 기각된 것 — 손대면 안 되는 4건

에이전트들이 올린 발견을 반증관이 무너뜨린 항목입니다. **오진단 상태로 고치면 멀쩡한 로직을 버리게 되므로 명시해 둡니다.**

**(가) `PROG_MULT_L11 = 3.3` 이 규정 5.3 위반 → 기각**
locked 도 3.3 입니다. 5.3은 **7/31 확정**이고 두 파일은 7/30 빌드입니다. "internal만 규정 위반"이 아니라 "internal·locked 공통 미전파"이며, 7/30 빌드가 7/31 결정을 담지 않은 것은 결함이 아니라 시간순입니다. 파일명 날짜를 빌드 내용 날짜로 오독한 판정이었습니다. → L11 로직을 결함으로 뜯지 마십시오. 5.3 전파는 "수리"가 아니라 다음 빌드 작업입니다.

**(나) `PM_Resume` 에 정지래치 가드가 없다 → 기각**
래치 검사는 상위 `PM_OnTick` 의 `canOpenNew = ... && !g_licStopped && !g_remoteStop` 에 이미 있어 진입은 차단됩니다. 버튼도 `LicHideGroup("BTN_")` + `if(licSt != DSH_ACTIVE) return;` 로 재그리기 자체가 없어 클릭 도달이 불가능합니다. 게다가 지적된 "포지션 0인데 MINING 표시"는 B1 이전 코드에서도 동일하게 발생합니다 = B1 귀속 실패. → 가드를 덧대는 수리 불필요.

**(다) 판 경계 이중계상으로 Resume 직후 재마감 반복 → 기각**
`CalcPMProfitSince(from)` 은 `from` 이전 딜을 집계에서 제외하므로 이중계상이 아닙니다. `PM_Start` 도 동일한 시각 기준입니다. 남는 것은 미결제분 이월인데, 새 목표를 즉시 달성해도 DONE 분기가 PM을 완전 정지시켜 루프가 닫히지 않습니다. → 회계를 개조하면 해결사 차감 조문을 깨뜨릴 위험이 이득보다 큽니다.

**(라) FORCECLOSE 후 재적용 시 PM 부활 → 기각**
`FC_PurgeRuntimeState()` 가 `PM_ClearState()` 로 GV(`_RUN/_SOFT/_ST/_TG`)를 삭제합니다. 재적용 시 `PM_RestoreState()` 가 false를 반환해 부활 기전이 없습니다. → `g_fcShutdown` 을 GV 영속화하면 "재적용 = 재가동" 사양이 파괴됩니다.
