## 2. 방법론 — 이게 진짜 수확입니다

### MQL5 아티클 22578 — "최고 성적 1개를 고르는 게 근본적 오류"

핵심 진단: 개발자들은 단일 지표(PF·샤프)를 최대화하는 **"best pass"** 를 고르는데, 이건 *"예쁜 숫자를 robust함과 혼동하는 것"* 입니다.

같은 수익률을 내는 두 설정이 있어도 하나는 **이웃 파라미터에서도 성적이 유지**되고 다른 하나는 **주변이 전부 나쁜 고립된 뾰족점**입니다. 표준 최적화는 후자를 고릅니다 — 과거 노이즈에 과적합된 쪽을요.

**대안: 파라미터 공간의 지형을 보라**

| 기법 | 내용 |
|---|---|
| **평탄대(plateau) 탐색** | 이웃에서도 성적이 유지되는 넓은 영역을 고른다 |
| **국소 안정성** | `이웃 평균 ÷ 표준편차` — 클수록 평탄 |
| **가우시안 스무딩** | 원 표면 vs 평활 표면을 비교해 극값이 인공물인지 판별 |
| **기울기 히트맵** | 급격히 변하는 구간 = 과최적화 지대 |
| **평행좌표** | 상위 5%가 여러 조합에 흩어져 있으면 robust, 한 점에 몰리면 fragile |
| **`FrameAdd()` 텔레메트리** | `OnTester()`에서 내장 지표 외 커스텀 값을 프레임으로 내보내 파이썬에서 후분석 |

인용: *"Strong optimization is not about maximizing profit, but about maximizing understanding of what exactly was optimized."*

그리고 실전 경고 하나 — *"최적화에서 PF 8을 넘는 설정은 forward 테스트에서 무너진다"*.

### MQL5 아티클 3279 — 워크포워드

전체 기간 **D**, 인샘플 창 **W**, 아웃샘플 스텝 **S** 로 굴립니다.

```
이동 횟수 N = (D − W) / S
예: 12개월 / 3개월 창 / 1개월 스텝 = 9회
```

권장 판정 기준:
- **일관성: 수익 난 forward 구간 비율 > 50%**
- **효율비 = forward 연환산 수익 ÷ 최적화 구간 연환산 수익**

MT5 설정: Forward 모드 "No", 최적화 기준 "custom" 필수, 실행 모드 Normal.

### MQL5 아티클 4347 — 몬테카를로

**무엇을 무작위화하나**: 트레이드 순서 **부트스트랩(복원 추출)**. 과거 거래 손익을 경험분포로 삼아 길이 N 시퀀스를 수천 개 재생성합니다.

산출 3종:
1. **최종 수익 분포** → 평균·표준편차(또는 중앙값·사분위)
2. **낙폭 제약 수익** — 낙폭이 임계를 넘으면 거래 중단하는 자본곡선 시뮬 (예: 자본 95% 유지선)
3. **정상성 검정** — 초기 vs 후기 거래 분포를 **Wilcoxon-Mann-Whitney**로 비교

판정 규칙: **평균 ÷ 산포**를 기준으로 삼는다. *"수익이 높고 산포가 작을수록 값이 커진다."*
분포가 유의하게 갈라지면(WMW 실패) 비정상성 = **특정 시장 국면에 과적합**됐다는 신호.

## 3. 우리 스크리너에 바로 적용했습니다

**제 스크리너가 정확히 그 오류를 저지르고 있었습니다.** composite 점수 1등을 고르는 방식이었는데, 그게 아티클 22578이 지적한 "best pass" 그 자체입니다.

수정: **평탄도 컬럼 추가.** 사다리 격자(정점층 × 정점랏 × 상승 × 하강)에서 각 축 ±1칸을 이웃으로 잡고, `이웃 목적값 평균 ÷ 표준편차`를 계산합니다. 고립된 봉우리는 표준편차가 커져 자동으로 강등됩니다.

```python
# 국소 안정성 = 이웃 평균 ÷ 표준편차 (MQL5 art.22578)
mean = sum(vals) / len(vals)
sd   = sqrt(sum((v - mean)**2 for v in vals) / len(vals))
stability = mean / sd
```

적용 후 상위권이 **거리 평탄 3.3 + 시간 감속** 계열로 수렴했고, 평탄도 10.9~13.8 구간에 몰렸습니다. 이건 뾰족점이 아니라 넓은 영역이라는 뜻입니다.

## 4. 권고 — 이 순서로

| 단계 | 무엇 | 비용 |
|---|---|---|
| **1** | 스크리너로 후보 5~10개 압축 | **지금 됨** · 백테스트 0회 |
| **2** | `mcp-mt5` 코드 검토 → 도입 or 참고해서 최소 러너 자작 | 반나절 |
| **3** | **워크포워드** — 인샘플 3개월 / 아웃샘플 1개월 롤링, 일관성 >50% 요구 | 자동 |
| **4** | **몬테카를로** — 트레이드 부트스트랩 → 평균÷산포, 낙폭 제약 시뮬 | 초 단위 |
| **5** | **평탄대 확인** — 채택 후보 주변 ±1칸도 같이 돌려서 성적이 유지되는지 | 후보당 4~8런 |

## 5. 이 프로젝트에 특히 중요한 경고

**기저율**: 이 레포에서 신규 대응 장치는 **6전 전패**입니다. 파라미터 스윕은 장치 신설과 다르지만, **과최적화 위험은 오히려 더 큽니다** — 조합이 수백 개면 우연히 좋아 보이는 게 반드시 나오기 때문입니다.

그래서 위 3·4·5번이 선택이 아니라 **필수**입니다. 특히:

- **단독 런은 판정이 아니라 관찰입니다** (이미 lessons에 있는 조문)
- **평탄대에 있지 않은 후보는 채택하지 마십시오.** 성적이 아무리 좋아도 이웃이 나쁘면 그건 노이즈에 맞춘 겁니다
- 백테스트 창을 극한 구간만 쓰면 **비용만 측정되고 편익은 미측정**입니다 (이것도 기존 조문)
