# MOMANTIC EA 계보 · 뚜껑갈이 · 버전관리 방법론 (골드·FX 공통)

> 이 문서는 `goldea`(골드)와 `fxea`(FX) **두 저장소가 공유하는 단일 진실**이다.
> 골드와 FX는 서로 다른 엔진이지만, **"엔진 1개 + 뚜껑갈이(리브랜딩)로 여러 브랜드"**라는
> 동일한 방법론과 버전관리 규칙을 쓴다. 새 브랜드/버전을 만들거나 로직을 고치기 전에 반드시 읽는다.

---

## 0. 한 줄 요약

각 계열에는 **마스터 엔진 딱 하나**가 있고, 시중의 여러 브랜드는 그 엔진의 **뚜껑갈이(겉껍데기 교체)**다.
**로직은 마스터에서만 고치고**, 브랜드들은 버전이 오를 때마다 마스터 엔진 위에 뚜껑만 다시 씌운다.

---

## 1. 핵심 원칙 (절대 규칙 — 골드·FX 공통)

1. **엔진 단일화**: 매매 로직·규정·게이트·정산은 **마스터 엔진(=internal 기준본)**에만 존재한다.
   골드=GoldMiner internal, FX=NEXUS-HEDGE internal.
2. **뚜껑은 딱 4가지만**: 화이트라벨(뚜껑갈이)이 따라가는 것은 오직 —
   ① **대시보드** ② **외부변수창(Inputs)** ③ **사용되는 이름들(브랜드 문자열·태그·copyright)** ④ **설정(디폴트값)**.
   **그 외 전부 마스터 엔진 그대로. 로직은 한 줄도 안 건드린다.**
3. **흡수 원칙(중요)**: 브랜드 고유였던 기능이 마스터 엔진에 흡수되면, 그건 이제 **엔진 소속**이다.
   → 뚜껑 레시피에서 **재추가 금지**(중복정의 = 컴파일 에러). 디폴트 값만 브랜드 방식으로 둔다.
   버전이 오를수록 **뚜껑은 점점 얇아진다.**
4. **버전 동기화**: 마스터 엔진 새 버전이 나오면 → 각 브랜드를 그 엔진으로 **재빌드(뚜껑 재이식)**.
   **엔진 내용은 같게, 브랜드별 버전 번호는 서로 달라도 된다.**
5. **베이스는 항상 `internal` 변형**: `locked`/`broadcast`/`dist`/`premium`은 일부 스위치를
   `const`로 박거나 배포용으로 가공한 파생본 → **기준 소스가 아니다.** 수정은 internal에서.
6. **매직넘버 불가침**: 운영 중인 계열의 base MagicNumber는 **절대 변경 금지**(바뀌면 기존 라이브
   포지션 인식 실패). 골드 base = **202604**.

---

## 2. 유지보수 규칙 (동일 내용을 여러 브랜드가 쓰기 때문)

- **버그 수정·로직 개선은 마스터 엔진(internal)에서만** 한다. 그다음 각 브랜드로 전파(뚜껑 재이식).
  브랜드 파일에서 직접 로직을 고치면 다음 버전에서 덮어써져 사라진다.
- 브랜드 파일을 고치는 경우는 **오직 뚜껑 4종(대시보드/Inputs/이름/디폴트)**뿐이다.
- **결함 이력·규정집은 계열 스킬의 references가 단일 출처**: 골드=goldminer-shd-dev, FX=nexus-hedge-fx-dev.
- **작업법(공통)**: 파일 직접 재작성 금지 → python 유일 앵커(count==1 assert) 치환 →
  정적 검증(괄호 3종 균형=원본 대비 변화 0 / 신규·폐기 심볼 배선 수 / 함수 중복·미정의·미호출 0 /
  브랜드 잔재 0) → (해당 시) 이중 빌드 → outputs 저장. F7 컴파일은 사장님 몫.

## 3. 골드 계열 계보 (`goldea`)

- **마스터 엔진**: **GoldMiner** (XAUUSD 마틴게일 그리드). 현재 internal 최신 = v5.5.x대
  (`goldea/src/mt5`의 `GoldMiner_v5_5_4_internal_*`).
- **매직 맵**(고정): base **202604** · SOLVER 777 · PM 555 · LHEDGE 111(격리 원장) · WKL 999.
- **화이트라벨(뚜껑갈이) 브랜드**:
  - **ANTGUARD GOLD**(앤트가드) — AGX 대시보드·개미 마스코트·스파크라인. 스킬: `antguard-gold-dev`.
  - **HansGold V1** — 고객사 **HIS INVEST** 전용. 이중 빌드(HIS_INVEST/INTERNAL, 3-define 차이).
    스킬/기록: `hansgold-whitelabel`.
  - **GoldGuard · GoldSun · GoldFerrari · PrimeGold** — 배포/브랜드 파생(archive).
  - (SideJobMaster 계열 일부 파일이 골드 사이즈로도 존재 — 확인 후 분류)
- **뚜껑 레시피 요지(HansGold 예)**: 이름 블랭킷 치환(MOMANTIC→브랜드, 잔재 0) · 대시보드
  DASH_COMPACT·계좌식별줄·러쉬 3칸 그리드 · Inputs 고객 12개/5그룹(나머지 const 숨김) ·
  설정 디폴트(LOT_SAFE·8시락 ON 등). **엔진 흡수분(강제청산 v2·SL토글 핸들러·EI 가드 등)은 재추가 금지.**

## 4. FX 계열 계보 (`fxea`)

- **마스터 엔진**: **NEXUS-HEDGE** (5통화쌍 포트폴리오 헷지). 현재 internal 최신 = **v7.10**
  (`fxea/src/mt5/MOMANTIC_NEXUS_HEDGE_v7_10_*`). MT4·MT5 병행, 핵심 로직 100% 동일.
- **화이트라벨(뚜껑갈이) 브랜드**:
  - **S-BOMB / SideJobMaster(SJM)** — 서버 payload상 "SideJobMaster SJM-SBOMB". 최신 S_BOMB v7.03.
  - **PrimeWin / WindsorPrime** — Windsor Brokers 향.
  - **FP MINER** — 파생.
  - **NEXUS_Monitor** — 모니터링 보조 EA(브랜드 아님).
- **뚜껑 4종 대응**: ① 대시보드(오렌지/블랙 MOMANTIC → 브랜드) ② Inputs(37개 파라미터 라벨/그룹)
  ③ 이름(eaName·copyright·태그) ④ 디폴트(운용 모드 SAFE/PRO/EXPERT 등).
- **FX 특유 주의**: 멀티심볼 `symbols` 배열·MDD·eaStatus·accountType(MICRO 포함) webhook 스키마를
  깨지 않는다(→ `올댓EA_서버연동_NEXUS_v7.10.md`). NEXUS LINK만 종목 교차.

## 5. 브랜드 추가/버전업 체크리스트

새 브랜드를 만들거나 마스터 새 버전으로 갈아끼울 때:

1. **마스터 internal 최신본 확보** → 계열 스킬 references(규정집·결함이력) 먼저 읽기.
2. **엔진 흡수 목록 확인** → 이번 버전에서 엔진에 들어간 기능은 뚜껑에서 재추가하지 않는다.
3. **뚜껑 4종만 이식**: 대시보드 / Inputs / 이름(블랭킷 치환, 잔재 0) / 디폴트.
4. **정적 검증**: 괄호 델타 0 · 브랜드 잔재 0 · 매직 불변 · 중복정의 0 · Inputs 그룹/개수 · 빌드 분기(define).
5. **이중(다중) 빌드**: internal(베이스) + locked/dist/broadcast 등 필요한 배포 변형.
6. **F7 → 실구동 화면 → (로직 변경 시) 백테스트** 사다리 통과 후 배포.
7. 산출물 + 변경요지를 저장소(`src/mt5`, `docs`)와 배포 파이프라인에 반영.

---

*각 계열 스킬(goldminer-shd-dev / antguard-gold-dev / nexus-hedge-fx-dev)의 references를 단일 출처로 삼는다.*
